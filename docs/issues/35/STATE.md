## Deviations from plan
- PR 2 fix round 2: the pub/sub baseline now waits for a PING on the subscriber link (S3/QA window), and a sequence 1 s or more below the last one resyncs (S1, `PUBSUB_SEQUENCE_REWIND_MAX`, a fixed constant like the other Q-B5 timings). No contract change: the message format `{v: 1, s, effects}` is unchanged.
- PR 2 (Gate 2 Q-B10), as implemented: dropping older effects alone would lose events (a remote frame of an earlier commit can be the only copy), so the order is enforced instead. Every commit that publishes takes a sequence from `P:seq` inside the COMMIT script (max(last + 1, Redis time in microseconds), so it never goes back even if the key expires) and records it per receiving instance in the group's high-water hash `P:q:<ns>:<gid>`; each message carries `s`. Because commits of a group are serialized by the lease and one channel delivers in script order, a task, after reading its group (one PRELOAD script: document, position, registry and its own high-water mark), waits until its instance received everything up to that mark (bound 1 s, `PUBSUB_BARRIER_MS`) and applies those effects first; only then does it run and flush. A message older than one already received is dropped (`pubsub_message_stale`). A link that lags past the bound is treated as stalled: resync (1001), then the link restarts from the current sequence. Message contract: `{v: 1, s, effects}`; architecture 12.3 (`P:seq`, `P:q`), 12.7 (`s`, the barrier) and 12.13 (log events) describe it since fix round 1 (PR 2); before that they did not, contrary to an earlier version of this line. Tests: multi-delivery "a task waits for earlier effects" (5 then 6), "a lagging link resyncs".
